# 扫描版电子书文字净化与重构经验及错题复盘 (Lessons Learned)

本文档归纳整理了从纸质扫描版 / 图片版电子书转换为高质量 Kindle 电子书（AZW3/MOBI）过程中的高频错题、根本原因分析（RCA）及工程最佳实践。

---

## 错题 1：盲信 OCR 标签导致目录爆炸与版面撕裂

### 现象
- 初始版本中，示例书 A 的目录膨胀至 200+ 条，示例书 B 的目录达 144 条。
- 侧边栏充斥着半句话、引文碎片；正文频繁被强行分页，阅读体验极差。

### 根因分析 (RCA)
- Docling / Vision OCR 在识别扫描版时，容易将短句、居中引文、加粗小节或列表头全部打上 `section_header` 标签。
- 转换管道简单地将所有 `section_header` 映射为 `<h2>`。在 Calibre 编译为 AZW3 时，默认对 `<h2>` 插入 `page-break-before: always`，导致大量非章节性文字被强行另起一页。

### 规范解决方案
1. **以原书印刷目录（Printed TOC）为最高准则**：
   - 提取扫描件目录页中的真实章节与子节列表，建立唯一的基准大纲（Schema）。
2. **两级目录分权（Two-Tier Heading Contract）**：
   - **Level 1 (`<h1>`, `.kindle-toc-level-1`)**：仅赋予主章节、自序、前言、附录与后记。
   - **Level 2 (`<h2>`, `.kindle-toc-level-2`)**：仅赋予原书纸质目录中明确收录的子节标题。
   - **Level 3 (`<h3>`, `.subsection-title`)**：正文内部未收录于纸质目录的小节标题，仅作正文字体加粗与间距美化，**绝不进入 Kindle 侧边栏目录，绝不强行分页**。

## 错题 2：按物理页码切分章节导致跨页断句错位

### 现象
- 上一章末尾的最后一句话出现在下一章的章节大标题之后（例如 Chapter 3 结尾句子 `和玲玲迟早会分手...` 出现在 Chapter 4 标题正下方）。

### 根因分析 (RCA)
- 纸质书排版通常紧凑，上一章节可能在第 23 页顶部占用了 1~2 行结束，随后在第 23 页中部开始新章节。
- 若按页码区间 `start_page <= page <= end_page` 切分，整页文本会被一刀切进新章节，造成前章尾句错位移入后章。

### 规范解决方案
- **基于精准文字锚点的流式分块算法（Anchor-Based Item Chunking）**：
  - 遍历 OCR 文本项序列，定位各章节标题出现的精确索引项 `start_idx`。
  - 章节内容严格划分为 `texts[start_idx : next_start_idx]`，彻底避免跨页首尾句错位。

## 错题 3：全局正则匹配导致子标题重复与正文被误转标题

### 现象
- 某些短语子标题（如示例书 B 中某个四字俗语小标题）在同一章内被反复匹配并生成了 4 个 `<h2>` 目录项；正文中包含该短语的段落被截断。

### 根因分析 (RCA)
- 全局扫描文本匹配子标题时，正文段落中出现的相同词汇被错误识别为小标题。

### 规范解决方案
1. **章节强绑定（Chapter-Bound H2 List）**：
   - 每个章节只维护属于本章节的子标题候选列表。
2. **单次消费机制（Consume-Once）**：
   - 某个子标题在章节内一旦命中匹配，立即从候选池中移除（`pop`），同一子标题绝不会在目录中重复出现。
3. **字数与格式约束**：
   - 必须满足独立短行（通常字符数 $\le 35$）或明确的标头标签才触发子节匹配。

## 错题 4：通用去噪正则误伤序言作者署名

### 现象
- 通用广告/去噪脚本将序言中的作者信息（如 `◎金鐘`、`◎司徒華`、`◎謝志偉`、`◎陳破空`）一并抹除。

### 根因分析 (RCA)
- 广告去噪规则过度泛化（如将所有以特殊符号开头的短行直接清空）。

### 规范解决方案
- **分层清洗与署名保留契约**：
  - 明确识别 `◎...` 或 `作者：...` 模式，将其提取为 `<p class="chapter-author">` 语义结构，置于章节主标题下方。
  - 广告去噪规则仅针对特征极强的联系方式、QQ号、书店网址等高危噪声。

## 错题 5：EPUBCheck 5.3.0 文件名与路径校验

### 现象
- 内部生成的 XHTML 文件包含空格或非 ASCII 字符时，触发 EPUBCheck `PKG-010` 和 `RSC-020` 严重警告。

### 规范解决方案
- 在 `ebook_kindle/normalize.py` 中对所有解包/重构的 EPUB 文件名进行纯 ASCII 标识符重命名（如 `section_0001.xhtml`），并同步更新 `content.opf`、`toc.ncx` 和 `nav.xhtml` 中的所有内部引用链接。

## 错题 6：扫描件底纹/透明水印碎裂插入导致段落截断与假 H3 生成

### 现象
- 读者在 Kindle 阅读时，正文中间经常夹杂类似 `7239@1236`、`001.com`、`98637246 1aohan001.com`、`77457 3637246`、`0:1040 节店` 等莫名符号与数字。
- 更严重的是，整句话被水印从中间切断，后半句被模型打上 `section_header` 标签，直接被渲染成 `<h3 class="subsection-title">`，导致正文支离破碎。
  - *典型案例*：前半句 `以实现邓所谓“杀`，后半句变成假 H3 `<h3 class="subsection-title">二十万人，保二十年稳定”的目标。</h3>`。
  - *其他案例*：`曹操瀚资讯 说` 撕裂为两截；`更有甚 77457 3637246 者` 撕裂“更有甚者”；`萎绕上书店...靡` 撕裂“萎靡”；`经 1001.com 济放缓` 撕裂“经济放缓”。

### 根因分析 (RCA)
- 扫描底本中存在第三方网店或盗印者添加的透明半角水印（如“某某线上书店 / QQ: 12345678 / www.example-shop.com”）。
- OCR 识别时，由于点阵低分辨率或被字迹遮挡，水印被拆裂为畸变碎屑。
- 基础清洗正则仅匹配完整关键词（如店名拼音 `shopname`），对 OCR 错别形态（首字母错认、`001.com` 残片、单独连续数字）漏检。
- 版面分析模型（Docling Layout）将夹在水印和孤立换行间的短行误判为 `section_header`，使断句后半截直接升级为标题。

### 规范解决方案
1. **多重模糊水印清洗正则池（Fuzzy Watermark Eraser）**：
   - 覆盖变异域名：`[a-zA-Z0-9_\.]*(?:shopname|hopname|shapname)[a-zA-Z0-9_\.]*`、`00[1l]\.com`（按具体水印写进该书 config 的 `drop_patterns`）。
   - 覆盖碎裂 QQ 与纯数字序列：`(?<!\d)(?:2Q|QQ|Q0|0Q)\s*[:：]?\s*[\d\s\-\|]*`，以及该水印号码 OCR 后的残段。
   - 覆盖被错录的出版社底页与外文信函末尾的电话、传真、邮箱（如 `E-mail :info@example.com`、`someone@example.org`、`ISBN` 条码等）。
   - 覆盖数字加符号杂音：`\d{3,}[@#\$%&*]\d{3,}`。
2. **严苛的小标题准入验证（`is_valid_h3` 守门机制）**：
   - 任何疑似小标题必须通过验证：严禁包含任何域名、纯数字或水印词根；严禁以逗号、冒号、句号等句末标点结尾；严禁包含断句残片；必须具备至少 2 个以上有效中文字符。未通过者自动降级为正文文本，并入段落缓冲区自然拼接。
3. **固定搭配与关键名句语义缝合（Phrase Stitching）**：
   - 在水印剥离前后，通过规则流自动将被截断的固定词汇缝合（如恢复“更有甚者”、“学者许志永”、“萎靡”、“经济放缓”、“杀二十万人”等），保障全书段落行云流水。

## 错题 7：OCR 汉字及标点形近字混淆与段落粘连

### 现象
- 正文出现固定模式的形近错字：如文革或六四事件中将“八九”误识为“入九”；将“自由”误识为“白由”；将鲁迅误识为“鲁述”；将“偷奸耍滑”误识为“偷好耍滑”；将“全世界讨厌”误识为“全世界讨厥”；将“性格张扬”误识为“性格张拇”；将“笑贫不笑娼”误识为“笑贫不笑妈”。
- 标点符号异常：闭引号 `」` 频繁被 OCR 误识为英文字母 `J`（如 `问：“你们的文明过头也叫文明吗？J 2014年12月`、`怒吼道：“关你屁事！J 2013年9月9日`）。由于段落合并算法只识别标点为段末，字母 `J` 被当成句子中段，导致后接的新段落被错误粘连并入前一段。

### 根因分析 (RCA)
- 汉字在低清或粗体扫描下，字形相似特征点极其接近（入/八、白/自、述/迅、厥/厌、拇/扬、妈/娼）。
- 弯角直角引号在倾斜扫描中极易被识别为大写英文字母 `J`。

### 规范解决方案
1. **语义级高频 OCR 错字置换流（OCR Confusion Correction Pipeline）**：
   - 建立正向规则表，在段落拼接前执行精准语义置换（涵盖八九、自由、鲁迅、偷奸耍滑、讨厌、张扬、笑贫不笑娼、根深蒂固、大一统、铜臭熏天、红尘滚滚、2011年等）。
2. **标点修正与粘连段落主动裂变（Quote Repair & Paragraph Split）**：
   - 将 `[？！。]\s*J\s*` 统一纠正为引文闭引号 `？”` 或 `！”`。
   - 在段落合并模块中，引入正则 `re.split(r"(?<=[」”’])\s+(?=[一二三四五六七八九十\d一-鿿])", text)`，遇到引号后紧随的日期或下一句时，强制切断并作为独立新段落排版，杜绝不同场景混为一谈。

## 错题 8：繁简转换策略与排版符号规范化

### 现象
- 港台出版的书籍原始扫描件为繁体中文。用户在电子书阅读器上偏好简体中文阅读。若仅做逐字繁简替换，常存在两岸用词不当、异体字残留、以及繁体直角引号（`「」` `『』`）与简体通用引号（`“”` `‘’`）混杂不规范的问题。

### 根因分析 (RCA)
- 简单的单字字典替换无法处理一繁对多简（如“發/髮”、“幹/乾/干”、“復/複”）的上下文语义分词。
- 标点体系未做统一标准化适配。

### 规范解决方案
1. **集成权威 OpenCC `t2s` 词级分词转换引擎**：
   - 采用基于词典的最大匹配算法（OpenCC t2s），全书覆盖标题、目录、正文、作者署名与引文注释，确保“头发/发展”、“复出/复杂”等精准转简，实现 100% 地道规范简体中文。
2. **符号规范化（Punctuation Normalization）**：
   - 繁体直角引号全面转换为现代汉语通用弯引号：`「...」` ➔ `“...”`，`『...』` ➔ `‘...’`。
   - 语言元数据统一声明为 `zh-CN`。

## 总结：扫描书文字净化重构全流程检查清单 (Complete Checklist)

1. [ ] **印刷目录对齐**：提取扫描目录页作为唯一标准，H1/H2 严格 1:1 映射，无膨胀碎片。
2. [ ] **流式锚点分块**：按文本项索引划定章节边界，严禁跨页首尾句错位。
3. [ ] **底纹水印清零**：全面过滤畸形域名、碎裂 QQ、电话、传真、邮箱及 `\d+@\d+` 杂音。
4. [ ] **假标题防范**：`is_valid_h3` 守门，严防断句、半截话、水印被升格为标题。
5. [ ] **关键短语缝合**：对被水印破坏的固定名句与短语执行语义缝合修复。
6. [ ] **OCR 错字校正**：纠正“入九/八九”、“白由/自由”、“鲁述/鲁迅”等典型形近误识。
7. [ ] **标点拆段**：修复 `？J` 为引文闭引号，并主动拆分粘连的新段落。
8. [ ] **繁简标准化**：全书 OpenCC t2s 转简，引号转换为标准双弯引号 `“”`。
9. [ ] **格式合规校验**：EPUBCheck 0 errors, 0 warnings，NCX 目录树层级严密。
10. [ ] **真机同步与缓存清理**：同步至 Kindle `/Volumes/Kindle/documents/`，清理陈旧 `.sdr` 缓存。
